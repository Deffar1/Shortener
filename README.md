# FastAPI + Aiogram Telegram Bot

Современный асинхронный Telegram-бот с API на базе FastAPI для создания и управления короткими ссылками. Проект спроектирован с учетом высоких нагрузок, поддерживает работу с двумя типами баз данных (PostgreSQL или MongoDB) на выбор, использует Redis для кэширования и управляется пакетным менеджером `uv`.

## 🛠 Технологический стек

* **Python:** 3.13
* **Web Framework:** FastAPI (Uvicorn)
* **Bot Framework:** Aiogram 3.x
* **Базы данных:** PostgreSQL / MongoDB (на выбор)
* **Кэш:** Redis
* **Пакетный менеджер:** uv
* **Контейнеризация:** Docker, Docker Compose

## 📡 API Эндпоинты

Сервис предоставляет лаконичное REST API для работы со ссылками.

Все POST-запросы возвращают стандартизированную модель `ShortUrlDTO`:

```python
class ShortUrlDTO(BaseModel):
    url_id: str
    original_url: HttpUrl
    clicks: int
    created_at: datetime
    status_token: UUID
```

**Доступные маршруты:**

* `GET /{url_id}` — Выполняет редирект (HTTP 302 Found) на оригинальный URL. Считает клики.
* `POST /create` — Принимает JSON с полем `url` (тип `HttpUrl`). Создает короткую ссылку и возвращает `ShortUrlDTO`.
* `POST /stats` — Принимает JSON с полем `status_token` (тип `UUID`). Возвращает статистику по ссылке в виде `ShortUrlDTO`.

## 🤖 Telegram Бот

Встроенный Telegram-бот предоставляет удобный интерфейс для взаимодействия с сервисом напрямую из мессенджера.

### Команды бота:

* `/start` — Приветственное сообщение и инструкция по использованию.
* `/create <URL>` — Сократить ссылку (например: `/create https://google.com`).
* `/stats <TOKEN>` — Получить статистику переходов по секретному токену (выдается при создании).
* **Отправка текста (ID или короткой ссылки)** — Бот автоматически распознает ссылку/ID в чате и покажет оригинальный URL, на который она ведет.

### 📝 Кастомизация сообщений

Все тексты бота вынесены в отдельный файл `src/bot/messages.py`. Это позволяет легко изменять копирайт без вмешательства в логику хендлеров. Сообщения используют метод `.format()`, куда передаются нужные аргументы (например, `{name}`, `{url_id}`, `{clicks}` и т.д.). Бот поддерживает `parse_mode="markdown"`.

## 🏗 Архитектура и High-Load паттерны

Проект спроектирован с упором на отказоустойчивость, масштабируемость и принципы чистой архитектуры.

### 1. Слоистая архитектура

Сервис строго разделен на независимые слои (Controller -> Service -> Repository -> DB), что позволяет легко менять бизнес-логику или базы данных без переписывания всего кода:

```text
[ FastAPI Endpoints / Aiogram Handlers ]  <-- Слой представления (Routing/UI)
                 ↓
           [ URLService ]                 <-- Слой бизнес-логики (Кэширование, валидация)
                 ↓
 [ BaseRepository (Postgres/Mongo) ]      <-- Слой доступа к данным (Абстракция БД)
                 ↓
    [ Database (Postgres/Mongo) ]         <-- Физическая БД
```

### 2. Умное управление сессиями и Middleware

Открытие сессий баз данных происходит изолированно на каждый запрос, что предотвращает утечки памяти и race condition.

* **FastAPI Log Middleware:** Замеряет время обработки каждого HTTP-запроса, логирует эндпоинты, статусы кодов и отлавливает необработанные исключения.
* **Aiogram Database Middleware:** Динамически определяет тип БД, создает нужный репозиторий (`PostgresRepository` или `MongoRepository`), инициализирует `URLService` и инжектит его напрямую в хендлеры бота. Гарантирует закрытие соединений после завершения обработки апдейта Telegram.

### 3. Graceful Shutdown и отказоустойчивость

* При старте корректно инициализируются подключения к БД и Redis, а также запускаются фоновые задачи (Telegram-бот и Click Flusher).
* При остановке происходит **Graceful shutdown**: приложение дожидается завершения текущих задач, отменяет фоновые воркеры без потери данных и безопасно закрывает сессии баз данных. При сетевых перебоях данные сохраняются.

### 4. Тотальное логирование

По всему приложению раскидано подробное логирование (через `logger`). Фиксируются этапы подключения к БД, время выполнения запросов, ошибки парсинга, отмены задач при выключении и любые внутренние сбои.

## 🚀 Настройка и Запуск

### Требования

* Docker и Docker Compose
* *Опционально (для локальной разработки):* [uv](https://docs.astral.sh/uv/getting-started/installation/)

### Настройка окружения

Создайте файл `.env` в корне проекта.

```env
# Общие настройки базы данных
DB_HOST=postgres_db
DB_USER=username
DB_PASS=sercet_password
DB_NAME=shorturls
DB_TYPE=postgres # или mongo

# Настройки PostgreSQL
POSTGRES_POOL_SIZE=10
POSTGRES_MAX_OVERFLOW=20

# Настройки MongoDB
MONGO_COLLECTION=links

# Настройки Redis
REDIS_HOST=localhost
REDIS_MAX_CONNECTIONS=10
REDIS_URL_TTL=604800

# Настройки сервиса
SHORT_URL_LENGTH=6 # Длина slug-а ссылки
CLICKS_FLUSH_INTERVAL=5 # Частота сбора кликов в БД в секундах
BOT_TOKEN=secret_bot_token # Токен Telegram бота
```

### Запуск через Docker (Рекомендуется)

**Вариант 1: Запуск с PostgreSQL**
Команда поднимет: FastAPI + Бот, Redis и PostgreSQL.

```bash
docker compose --profile postgres up -d
```

**Вариант 2: Запуск с MongoDB**
Команда поднимет: FastAPI + Бот, Redis и MongoDB.

```bash
docker compose --profile mongo up -d
```

### Локальная разработка (без Docker)

*(Redis и выбранная БД должны быть запущены локально)*

1. Синхронизируйте зависимости (создаст виртуальное окружение `.venv`):

```bash
uv sync
```

2. Активируйте виртуальное окружение:

```bash
# Для Linux/macOS
source .venv/bin/activate
# Для Windows
.venv\Scripts\activate
```

3. Запустите проект:

```bash
uv run uvicorn main:app --reload
```

## 📜 Историческая справка и логика решений

Целью проекта было применить накопленные знания в реальном сервисе, с расчетом на отказоустойчивость.

Изначально сервис был написан на базе MongoDB, но после изучения SQLAlchemy я захотел не только внедрить реляционную базу данных, но и сделать возможность переключаться между ними при запуске. Заодно смог реализовать абстрактный интерфейс (`BaseRepository`) и паттерн "Репозиторий".

Далее решил добавить Redis для высоких нагрузок. Столкнулся с проблемой: нужно было обновлять счетчик переходов по ссылке, не обращаясь каждый раз к базе данных (чтобы не положить БД при наплыве трафика).
Решил эту проблему с помощью фонового сборщика (`periodic_click_flusher`): он атомарно забирает накопленные клики из Redis и отправляет их батч-запросом в базу данных. При этом он спроектирован так, что не производит удаление из Redis, если запись в БД не удалась по каким-либо причинам (например, мигнула сеть). Это гарантирует 100% сохранность статистики даже при сбоях.

> **Примечание:** Весь сервис написан полностью вручную. Сгенерированы были только Lua-скрипты для Redis и тексты сообщений для Telegram-бота. Суммарно на проектирование, разработку и отладку проекта ушло около **30 часов**.
